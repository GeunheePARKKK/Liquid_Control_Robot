## 왜 수평이 정답이 아닌가

가속하는 차 안의 물컵을 생각하면 된다. 컵을 수평으로 붙잡고 있으면 물은
뒤로 쏠린다. 액체 입장에서는 중력과 관성력의 **합력**이 진짜 아래쪽이므로,
컵 바닥을 그 합력에 수직으로 놓아야 수면이 컵 기준으로 평평해진다.

| 상황 | 합력 | θ_ref |
|---|---|---|
| 정지·등속 | 중력만 | **0** — 수평이 정답 |
| 가속 중 | 중력 + 관성력 | **≠0** — 기울여야 정답 |
| 경사면 + 가속 | 둘의 합 | 자동으로 합성 |

**수평제어와 안티슬로싱이 별개의 모드가 아니다.** 한 식이 두 경우를 모두 덮는다.
경사면에 서 있으면 `a_linear` 가 0 이라 `θ_ref` 도 0 이 되어 자동으로 절대 수평이 된다.

> 초기에 "1. 수평제어 / 2. 안티슬로싱" 으로 모드를 나누려 했으나 그렇게 하면
> 경계에서 채터링이 생기고, 그 덜컥거림 자체가 슬로싱을 새로 만든다.
> 험지 주행처럼 경사와 가속이 동시에 오는 상황도 어느 모드로도 처리가 안 된다.

## 무엇이 바뀌었나

1단계에서 **목표각 한 항만** 추가됐다.

```
1단계 :  θ_ref = 0                    →  motor_cmd = −θ_base
2단계 :  θ_ref = atan(a_linear / g)   →  motor_cmd = θ_ref − θ_base
```

### 계산 순서

```cpp
// 1. 중력 성분 제거 — 가속도계는 기울어져 있기만 해도 중력을 읽는다
float one_g   = G_LSB * g_scale;
float a_lin_y = ay - one_g * sinf(pitch_filtered * DEG_TO_RAD);
float a_lin_x = ax - one_g * sinf(roll_filtered  * DEG_TO_RAD);

// 2. 합력이 수직에서 벗어난 각도
float raw_ref_p = atan2f(a_lin_y, one_g) * RAD_TO_DEG * DIR_ACC;

// 3. 노이즈가 크므로 목표각을 따로 저역통과
ref_pitch = ACC_LPF * raw_ref_p + (1 - ACC_LPF) * ref_pitch;

// 4. 모터는 차체 기준으로 도므로 차체 자세를 뺀다
want_pitch = (ACC_GAIN * ref_pitch - pitch_filtered * GAIN) * DIR_PITCH;
```

중력을 뺄 때 쓰는 각도가 1단계에서 만든 `θ_base` 다. `g_scale` 은 부팅 시
정규화한 값이라 1g 에 해당하는 LSB 가 `G_LSB × g_scale` 이다.

### 새 파라미터

| 이름 | 기본 | 명령 | 뜻 |
|---|---|---|---|
| `ACC_GAIN` | **0** | `ag<값>` | 합력 항 게인. **0 이면 1단계와 완전히 동일** |
| `DIR_ACC` | +1 | (코드) | 합력 목표각 부호. 실측으로 정함 |
| `ACC_LPF` | 0.2 | `ad<값>` | θ_ref 전용 저역통과 |
| `ACC_REF_LIMIT` | 20° | (코드) | θ_ref 자체의 상한 |

### 출력에 `ref_*` 추가

```
pitch:12.34,ref_pitch:-4.20,cmd_pitch:-12.10,act_pitch:-11.8,roll:...
                  ↑ 합력 목표각
```

`ACC_GAIN` 이 0 이어도 계산되어 찍힌다. **모터를 켜지 않고 부호를 확인**할 수 있다.

## 기본값을 0 으로 둔 이유

부호가 반대면 가속할 때 액체를 **더** 흔드는 쪽으로 기울인다.

수평제어는 부호가 틀리면 트레이가 반대로 기우는 것이 바로 보인다. 그런데
합력 항은 **가속하는 순간에만** 나타나므로 눈으로 알아채기 어렵다.
그래서 처음 올리면 1단계와 똑같이 동작하게 두고, 숫자로 확인한 뒤 켠다.

되돌릴 때도 `stop` 보다 **`ag0`** 이 먼저다. 수평제어는 계속 살아 있다.

## 부호 확인 절차

### 1) 모터 없이 부호만

`arm` 하지 않고 IMU 를 책상에서 한 방향으로 민다. `ref_pitch` 를 본다.

| 보드 **+Y 방향**으로 밀었을 때 | 판정 |
|---|---|
| `ref_pitch` 음수 | ✅ 맞다 (`DIR_ACC = +1` 유지) |
| `ref_pitch` 양수 | ❌ `DIR_ACC` 를 `−1` 로 |

음수여야 하는 이유. 컵을 +Y 로 가속하면 물은 −Y 로 쏠린다. 수면을 컵 기준으로
평평하게 두려면 컵의 +Y 쪽을 내려야 한다. 우리 규약에서 `+pitch` 는 +Y 가
올라가는 것이므로 목표는 음수가 된다.

roll 은 `+roll` 이 +X 가 **내려가는** 것이라 부호 방향이 pitch 와 반대다.

### 2) 정지 상태 확인

- 책상에 가만히 → `ref` 가 0 근처
- **기울여 놓고 가만히 → 이때도 0 근처**

기울기만으로 `ref` 가 생기면 중력 제거가 잘못된 것이다. `g_scale` 과 `θ_base`
를 먼저 의심한다. **이 경우 `ACC_GAIN` 을 올리면 안 된다.**

### 3) 게인 상승

```
ag0.3  →  ag0.6  →  ag1.0
```

각 단계에서 IMU 를 밀었다 세웠다 하며 트레이가 가속 반대쪽으로 기우는지 본다.

### 기록할 것

| 항목 | 값 |
|---|---|
| `DIR_ACC` 최종 부호 | (미측정) |
| 정지 시 `ref` 편차 | (미측정) |
| 안정적인 최대 `ACC_GAIN` | (미측정) |
| `ACC_LPF` 적정값 | (미측정) |

## 아직 없는 것

**ZV 입력성형이 없다.** 지금은 `θ_ref` 가 바뀌는 즉시 그대로 따라가므로,
목표각의 급변 자체가 슬로싱을 새로 만들 수 있다. 3단계에서 `θ_ref` 에
Convolved ZV 를 걸어 그 성분을 없앤다.

**지연이 150~180ms 로 측정돼 있다.** 슬로싱 주기 420ms 의 36% 라 위상 여유가
부족하다. `CMD_LPF`(57ms)·슬루·낮은 `Kp` 가 원인이며, 3단계 전에 손봐야 할 수 있다.
