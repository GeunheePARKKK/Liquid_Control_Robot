## 축 정의

| 이름 | 회전축 | 의미 |
|---|---|---|
| **pitch** | **X축 중심 회전** | 앞뒤 기울기 |
| **roll** | **Y축 중심 회전** | 좌우 기울기 |

---

## 센서 → 각도 매핑

```cpp
// pitch : X축 중심 회전
float rate_pitch = ((float)gx - gyro_bias_x) / GYRO_LSB;                    // X축 자이로
float pitch_acc  = atan2((float)ay,  sqrt(ax*ax + az*az)) * (180.0 / PI);   // Y축 가속도

// roll : Y축 중심 회전
float rate_roll  = ((float)gy - gyro_bias_y) / GYRO_LSB;                    // Y축 자이로
float roll_acc   = atan2((float)-ax, sqrt(ay*ay + az*az)) * (180.0 / PI);   // X축 가속도
```

| | 회전축 | 자이로 | 가속도 |
|---|---|---|---|
| pitch | X | `gx` | `ay` |
| roll | Y | `gy` | `-ax` |

> 회전축과 사용하는 가속도 축이 서로 다르다. X축 중심으로 돌면 Y축 가속도가
> 변하기 때문. 코드 읽을 때 혼동하기 쉬운 지점.

## 시리얼 출력 4개

```cpp
Serial.printf("pitch:%.2f,pitch_acc:%.2f,roll:%.2f,roll_acc:%.2f\n",
              pitch_filtered, pitch_acc, roll_filtered, roll_acc);
```

| 출력 이름 | 변수 | 정체 | 용도 |
|---|---|---|---|
| **`pitch`** | `pitch_filtered` | 상보필터 결과 (자이로+가속도 융합) | **제어 입력** |
| `pitch_acc` | `pitch_acc` | 가속도계 단독 계산값 | 진단 전용 |
| **`roll`** | `roll_filtered` | 상보필터 결과 | **제어 입력** |
| `roll_acc` | `roll_acc` | 가속도계 단독 계산값 | 진단 전용 |

- 단위: **도(°)**, 4개 전부
- 기준: **중력 기준 절대 각도** (베이스 대비 상대각이 아님)
- 출력 주기: 10Hz (제어 루프는 100Hz)
- 포맷: `이름:값` 쉼표 구분 — 아두이노 시리얼 플로터 호환

### `_acc` 를 함께 출력하는 이유

제어에 쓰는 값이 아니라 **필터가 제대로 동작하는지 보는 참고선**이다.

| 관측 | 의미 |
|---|---|
| 정지 시 `pitch` ≈ `pitch_acc` | 정상 (실측 0.03° 이내) |
| 움직일 때 둘이 벌어짐 | 정상 — 가속도계가 관성에 오염된 것 |
| 둘이 **반대 방향**으로 움직임 | 자이로 부호 반전 필요 |
| 정지 후에도 안 붙음 | 드리프트 발생 |

제어 코드로 넘어가면 `_acc` 두 개는 디버깅 목적 외에는 빼도 된다.

## 모터 대응

### 확정된 것 — 물리 축과 모터 (2026-08-29 실측)

무동력 상태에서 각 축을 손으로 돌려 확인했다. 돌린 축의 모터만 위치가 변했다.

| 물리 축 | 모터 CAN ID | Master ID |
|---|---|---|
| **바깥축** | `0x01` | `0x00` |
| **안쪽축** | `0x02` | **`0x11`** |

> Master ID 가 `0x11` 인 이유는 MIT 모드 명령 주소(`0x001`/`0x002`)와 겹치지
> 않게 하기 위함이다. 겹치면 한 모터가 다른 모터의 피드백을 명령으로 읽어
> 폭주한다. [`모터_수평제어_MIT.ino_변경이력.md`](%5B1%EB%8B%A8%EA%B3%84%5D%20%EC%88%98%ED%8F%89%EC%A0%9C%EC%96%B4/%EB%AA%A8%ED%84%B0_%EC%88%98%ED%8F%89%EC%A0%9C%EC%96%B4_MIT.ino_%EB%B3%80%EA%B2%BD%EC%9D%B4%EB%A0%A5.md) 참고.

### 미확정 — pitch/roll 과 모터

코드의 `CAN_ID_PITCH` / `CAN_ID_ROLL` 은 **임시 배정**이다.

`pitch` 는 "IMU 보드의 X축 중심 회전"인데, 시운전 동안 IMU 를 손에 들고 있어
짐벌의 어느 축과도 고정된 관계가 없었다. **차체에 실장한 뒤** 아래 순서로 확정한다.

1. IMU 의 +X축이 짐벌의 어느 축과 나란한지 확인
2. 그 축을 담당하는 모터를 `CAN_ID_PITCH` 에 배정
3. `DIR_PITCH` / `DIR_ROLL` 부호를 다시 확인

### 참고 — 문서 간 표기가 엇갈린다

X/Y 라는 이름은 쓰지 않기로 했다. 출처마다 반대로 적혀 있기 때문이다.

| 출처 | Pitch | Roll |
|---|---|---|
| 논문 + 이전 서보 코드 | Y축 모터 | X축 모터 |
| 한이음 보고서 | Motor_X | Motor_Y |

그래서 코드에서는 담당 각도로 이름 붙였다 (`CAN_ID_PITCH`, `CAN_ID_ROLL`).

## 부호 방향 (검증 완료)

기준은 **브레이크아웃 보드에 인쇄된 X / Y / Z 축 화살표**다.
로봇의 앞뒤좌우가 아니라 보드 자체의 축을 기준으로 판단한다.

### 코드에서 유도한 예상

가속도계는 **위를 향한 축이 +1g** 를 읽는다 (ST 표준 규약).

```cpp
pitch_acc = atan2( ay, ...)    // ay > 0  →  pitch +
roll_acc  = atan2(-ax, ...)    // ax < 0  →  roll +
```

| | 조건 | 물리적 의미 |
|---|---|---|
| **`+pitch`** | `ay > 0` | 보드의 **+Y 축 쪽이 위로** 들림 |
| **`+roll`** | `ax < 0` | 보드의 **+X 축 쪽이 아래로** 내려감 |

### 실측 확인 결과 ✅ (2026-08-27)

**예상과 실측이 일치. 부호 반전 불필요, 코드 수정 없이 그대로 사용.**

| 항목 | 예상 | 실측 |
|---|---|---|
| +Y 축 상승 시 `pitch` | `+` | **`+` 일치** |
| +X 축 하강 시 `roll` | `+` | **`+` 일치** |

확정된 부호 규약.

| 부호 | 물리적 상태 |
|---|---|
| `pitch > 0` | 보드 **+Y 축 쪽이 위로** 들림 |
| `pitch < 0` | 보드 **+Y 축 쪽이 아래로** 내려감 |
| `roll > 0` | 보드 **+X 축 쪽이 아래로** 내려감 |
| `roll < 0` | 보드 **+X 축 쪽이 위로** 들림 |

> **제어기는 이 부호를 줄이는 방향으로 모터를 구동해야 한다.**
> 반대로 걸면 기울어짐을 키우는 방향이 되어 발산한다.

### 재확인 절차

센서를 다시 장착하거나 방향을 바꾸면 아래 절차로 다시 확인한다.
코드 수정 없이 기존 시리얼 출력만 보면 된다.

1. 보드를 평평하게 두고 `pitch` / `roll` 이 0 근처인지 확인
2. **+Y 축 쪽을 들어올린다** → `pitch` 부호 기록
3. 평평하게 되돌린 뒤 **+X 축 쪽을 내린다** → `roll` 부호 기록
