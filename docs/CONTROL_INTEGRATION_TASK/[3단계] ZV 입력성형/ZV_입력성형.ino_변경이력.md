## 왜 목표각에만 거는가

성형은 `θ_ref` 에만 건다. 수평 항에는 걸지 않는다.

```
want = ACC_GAIN·θ_ref  −  GAIN·θ_base
         ↑ 기준값                ↑ 외란 측정값
```

`θ_ref` 는 **우리가 트레이를 어디 두고 싶은지**다. 입력성형은 원래 기준값에
거는 기법이다.

`θ_base` 는 **차체가 이미 기울어버린 것**을 잰 값이다. 여기에 성형을 걸면
반주기 동안 트레이가 수평을 못 지킨다. 그러면 액체 입장에서 유효중력 방향
자체가 트레이 기준으로 기운다. 성형으로 막으려던 진동보다 훨씬 큰 1차
외란이다. **진동을 줄이려다 더 큰 것을 만든다.**

---

## 무엇이 바뀌었나

2단계에서 목표각과 제어식 사이에 한 단이 끼었다.

```
2단계 :  θ_ref  ──────────────→  want = ACC_GAIN·θ_ref − GAIN·θ_base
3단계 :  θ_ref  ──[ ZV ]──→ θ_shaped → want = ACC_GAIN·θ_shaped − GAIN·θ_base
```

### 셰이퍼

목표각을 나눠 반주기 간격으로 보낸다. 앞 임펄스가 만든 출렁임을 뒤 임펄스가
반대 위상으로 때려 지운다.

```
K   = exp(-ζπ / √(1-ζ²))            한 주기 뒤 진폭비
Td  = 1 / (f √(1-ζ²))               감쇠 주기

ZV  : [1, K] / (1+K)          at 0, Td/2
ZVD : [1, 2K, K²] / (1+K)²    at 0, Td/2, Td
```

2.4Hz · ζ=0.02 에서 `K = 0.9391`, `Td = 417ms`, 반주기 21샘플(100Hz).

| | 진폭 |
|---|---|
| ZV | 0.5157, 0.4843 |
| ZVD | 0.2660, 0.4995, 0.2345 |

### 두 축 모두에 건다

이전 서보 구조는 pitch 만 성형하고 roll 버퍼는 선언만 해둔 채 쓰지 않았다.

### 새 파라미터

| 이름 | 기본 | 명령 | 뜻 |
|---|---|---|---|
| `ZV_ON` | **꺼짐** | `zv1` / `zv0` | **꺼두면 2단계와 완전히 동일** |
| `ZV_FREQ` | 2.40 Hz | `zf<값>` | 슬로싱 주파수. **실측해서 넣을 것** |
| `ZV_ZETA` | 0.02 | `zd<값>` | 감쇠비. 액체는 보통 0.01~0.05 |
| `ZV_MODE` | 2 | `zm<2\|3>` | 2=ZV, 3=ZVD |

`ACC_GAIN` 과 같은 방식이다. 올려도 아무것도 안 바뀌고, 확인한 뒤 켠다.

### 출력에 `zv_*` 추가

```
pitch:..,ref_pitch:..,zv_pitch:..,cmd_pitch:..,act_pitch:..,roll:..,...
                            ↑ 성형된 목표각
```

`ref_pitch` 와 `zv_pitch` 를 나란히 찍으므로 성형이 무엇을 했는지 로그에서
바로 보인다.

## 수치 검증

2차계(2.4Hz, ζ=0.02)에 성형 입력을 넣고 마지막 임펄스 0.5초 뒤부터 잔류
진동을 쟀다.

| | 잔류 진동 | 감소 |
|---|---|---|
| 성형 없음 | 80.45 % | — |
| **ZV** | **1.30 %** | 62배 |
| **ZVD** | **0.02 %** | 4080배 |

### 주파수를 틀렸을 때

여기가 중요하다. 슬로싱 주파수를 아직 실측하지 않았다.

| 실제 주파수 | 성형없음 | ZV | ZVD |
|---|---|---|---|
| 1.92 Hz (−20%) | 85.5 % | 23.9 % | **7.1 %** |
| 2.16 Hz (−10%) | 80.5 % | 11.5 % | **1.5 %** |
| **2.40 Hz (정확)** | 80.5 % | 1.3 % | 0.02 % |
| 2.64 Hz (+10%) | 80.6 % | 13.2 % | **2.3 %** |
| 2.88 Hz (+20%) | 80.5 % | 24.9 % | **7.7 %** |

**주파수를 확정하기 전에는 ZVD 를 쓴다.** ±20% 틀려도 7% 인데 ZV 는 25% 다.
지연은 두 배지만, 주파수를 모르는 채 ZV 를 쓰면 성형을 안 한 것보다 조금
나은 수준에 그친다.

주파수를 실측해 확정한 뒤에는 ZV 로 바꿔 지연을 절반으로 줄인다.

## 지연 예산 — 켜기 전에 봐야 한다

성형은 지연을 사서 진동을 지운다.

| 항목 | 지연 |
|---|---|
| 1단계에서 측정된 지연 | 150~180 ms |
| ZV 추가 | +104 ms |
| ZVD 추가 | +208 ms |
| **슬로싱 주기** | **420 ms** |

ZVD 를 얹으면 360~390ms, 주기의 **93%** 다. 이대로는 안티슬로싱 항이 제때
도착하지 못한다.

**`r` 로 슬루 지연을 먼저 줄여놓고 켤 것.** 2단계에서 `MAX_RATE` 30°/s 가
지령 변화율의 27% 를 잘라내고 있었다.

## `ZV_FREQ` 2.40 을 믿으면 안 된다

이전 서보 코드의 ZV 파라미터에서 역산한 값이다. 슬로싱 주파수는 **용기
형상과 액체 높이에 따라 변한다.**

```
원통 1차 모드 :  ω² = 1.841 (g/R) · tanh(1.841 h/R)
```

물이 반쯤 찼을 때와 가득 찼을 때가 다르다. 트레이 IMU 로 CNN 학습 데이터를
모으려던 것이 이 주파수를 추정하기 위한 것이었다.

### 실측 방법

1. 실제 용기에 액체를 담아 트레이에 올린다
2. `ag0` `zv0` 으로 두고 트레이를 툭 친다
3. 트레이 IMU 로 출렁임이 잦아드는 파형을 받는다
4. 영교차 간격에서 주기를, 진폭 감쇠에서 ζ 를 뽑는다

액체 높이를 바꿔가며 반복하면 CNN 학습 데이터가 된다.

## capture.py — 명령 여러 개

포트를 열면 보드가 리셋되어 시리얼로 걸어둔 설정이 날아간다. `--cmd` 가
쉼표 목록을 받아 한 줄씩 보내도록 고쳤다.

```

```

한 줄로 보내면 조용히 절반만 먹는다. `ag1.0,zv1` 을 통째로 보냈더니 스케치가
`ag` 접두로 받아 `"1.0,zv1".toFloat()` = 1.0 으로 처리하고 나머지를 버렸다.
