## 왜 MIT 모드로 바꿨나

### 문제

위치/속도 모드에서 **바깥축 모터가 목표 각도를 유지하지 못하고 왕복**했다.

| | 지령 | 실제 | |
|---|---|---|---|
| 안쪽축 | `+10.02°` | `9.98 ~ 10.04` | ±0.03° 안정 |
| 바깥축 | `-16.70°` | `-35.8 ~ +1.9` | **38° p-p, 1.75Hz** |

- 지령은 0.09° 이내로 고정이었다 → 제어 코드 문제 아님
- 진동 중심이 지령과 일치 → 목표는 제대로 받았으나 멈추지 못함
- 소프트웨어 제한 25° 를 넘어 -35.8° 까지 감 → 드라이버 내부 루프의 오버슛

### 원인

**두 드라이버의 파라미터가 사실상 동일했다.** CubeMars 로 양쪽을 읽어 비교한 결과.

| 항목 | `0x01` (발진) | `0x02` (안정) |
|---|---|---|
| Position KP | **54** | **54** |
| Position KI | 0 | 0 |
| Damping factor | **4** | **4** |
| VMAX | 30 | 30 |
| Speed KP / KI | 0.003703166 / 0.003926991 | 0.003630572 / 0.003926991 |
| CurrentBW | 1000 | 1000 |
| ControlMode | 2:Pos | 2:Pos |

게인이 같은데 한쪽만 발진하므로 **설정 차이가 아니라 바깥축의 큰 관성**이 원인이다.
바깥축은 안쪽 조립체 전체를 짊어진다. 감쇠비 `ζ = D / (2√(Kp·J))` 에서 `J` 가
커지면 `ζ` 가 작아져, 가벼운 축에서 멀쩡하던 게인이 무거운 축에서 발진한다.

### 위치/속도 모드로는 못 고치는 이유

내부 구조가 아래 캐스케이드다 (CubeMars 화면의 블록도).

```
Pdes → [PI] → Vdes → [PI] → iqref
```

- **감쇠(D) 항이 없다.** 감쇠는 `Damping factor` 와 속도 PI 에서만 나온다
- 게인이 **드라이버 플래시에 저장**되어 코드로 못 바꾼다.
  값 하나 바꿀 때마다 스케치를 내리고 `serial_bridge.ino` 를 올리고
  CubeMars 를 열어야 한다

### MIT 모드가 해결하는 것

프레임마다 Kp·Kd 를 실어 보내며 아래 임피던스 제어를 한다.

```
τ = Kp·(p_des − p) + Kd·(v_des − v) + t_ff
```

`v_des = 0` 이면 **Kd 가 "움직이면 반대로 제동"하는 점성 감쇠**가 되어
오버슛을 직접 잡는다. 지금 없는 바로 그 항이다.

> 매뉴얼 42p: *"When controlling position, kd cannot be assigned 0, otherwise it
> will cause the motor to oscillate and even go out of control."*
> — 증상과 정확히 일치한다.

| | 위치/속도 모드 | MIT 모드 |
|---|---|---|
| 제어법 | PI → PI 캐스케이드 | PD 임피던스 |
| 게인 위치 | 플래시 (툴로만 변경) | **매 프레임 전송 (코드에서)** |
| 적분항 | 있음 | 없음 |
| **감쇠항** | **없음** | **Kd 직접** |
| Kp 단위 | 속도루프 입력 | N/rad (물리적 강성) |

적분항이 없는 것은 이 시스템에서 오히려 장점이다. 이전 서보 구조에서도
비선형성 때문에 I·D 를 쓰면 발산해서 P 만 썼다.

## MIT 모드 프로토콜 (매뉴얼 42~43p)

CAN ID = `(제어모드 << 8) | 모터ID` 이고 **MIT 는 모드 0** 이므로 ID 는 모터 ID 그대로다.
위치/속도 모드의 `0x100 | ID` 와 다르다.

### 제어 프레임

| | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 |
|---|---|---|---|---|---|---|---|---|
| | pos[15:8] | pos[7:0] | vel[11:4] | vel[3:0]<br>kp[11:8] | kp[7:0] | kd[11:4] | kd[3:0]<br>t[11:8] | t[7:0] |

### 변환 범위 — 드라이버 설정과 반드시 일치

| 항목 | 범위 | 비트 | 비고 |
|---|---|---|---|
| pos | ±12.5 rad | 16 | PMAX |
| **vel** | **±30 rad/s** | 12 | **VMAX. 매뉴얼 기본 200 아님** |
| Kp | 0 ~ 500 N/rad | 12 | |
| Kd | 0 ~ 5 N·s/rad | 12 | |
| t_ff | ±10 N·m | 12 | TMAX |

> `VMAX` 는 이 드라이버가 30 이다. 매뉴얼 p48 이 "제어 명령을 보낼 때는 설정된
> 값과 일치시키는 것이 필수" 라고 명시한다. 200 으로 환산하면 속도가 6.7배
> 어긋난다. `GL60II_모터_설정_가이드.md` 5장 참고.

### 피드백 프레임

| | D0 | D1~2 | D3 | D4 | D5 | D6 | D7 |
|---|---|---|---|---|---|---|---|
| | ID \| ERR<<4 | POS | VEL[11:4] | VEL[3:0]<br>T[11:8] | T[7:0] | T_MOS | T_Rotor |

## 코드 구성

`모터_수평제어.ino` 에서 아래만 바뀌었다. 제어식·IMU·안전장치는 동일.

| 항목 | 변경 |
|---|---|
| CAN ID 접두 | `0x100` → `0x000` (`CAN_MODE` 상수) |
| 전송 함수 | `sendPosVel()` → `sendMIT()` |
| 속도 지령 | `VEL_LIMIT` (속도 제한) → `v_des = 0` (감쇠 기준) |
| 게인 | 없음 → `MOTOR_KP` / `MOTOR_KD` 매 프레임 전송 |
| 피드백 | 위치만 → 위치 + 속도 |
| 시리얼 명령 | `v<값>` 삭제, **`kp<값>` / `kd<값>`** 추가 |

초기값은 `Kp = 20`, `Kd = 1.0` 으로 낮게 잡았다.

> 명령 파싱에서 `kp` 를 `kd` 보다, 그리고 둘 다 `g`/`f`/`d` 보다 먼저 검사한다.
> `startsWith` 로 판정하므로 순서가 바뀌면 `kd1.5` 가 `d` 명령으로 잡힌다.

## 튜닝 순서

1. **`t`** — 두 모터가 왕복하면 MIT 통신 정상. 반응 없으면 `ControlMode` 확인
2. **`arm` 후 `kd` 를 올려가며 발진을 잡는다** ← 이번 문제의 핵심
   `kd0.5` → `kd1.0` → `kd2.0` … 떨림이 멎는 최솟값을 찾는다
3. **`kp` 로 강성 조정** — 목표에 못 미치면 올린다. 올리면 `kd` 도 같이 올린다
4. **`g` 를 1.0 까지** — 이때 비로소 기운 만큼 전부 보상한다

두 축의 관성이 다르므로 최종적으로는 축별로 Kp/Kd 를 분리해야 할 수 있다.
현재 코드는 두 축에 같은 값을 보낸다.

### 측정 결과 (2026-08-27)

`MIT_안전점검.ino` 로 목표를 영점에 고정한 채 게인만 바꿔가며 탐색했다.

| 항목 | 값 |
|---|---|
| 트레이를 잡는 최소 Kp | **1** |
| 왕복 없이 복귀하는 최소 Kd | **0.1** |
| 안정적인 최대 GAIN | (미측정 — 제어 스케치에서) |
| 축별 게인 분리 필요 여부 | (미측정) |

#### Kp 단독 (Kd = 0)

| Kp | 결과 |
|---|---|
| 1 | 밀면 여러 번 왕복하다 마찰로 겨우 수렴. 소리 없음 |
| 3 | **발산** |

매뉴얼 42p 의 "kd 를 0 으로 두면 발진하고 폭주한다" 가 그대로 재현됐다.
`τ = Kp·오차` 만 있으면 스프링에 관성만 매단 무감쇠 진동자라 수렴할 수 없다.

> 이전 서보 구조에서 P 만으로 됐던 것은 **서보 내부에 감쇠 루프가 있었기**
> 때문이다. MIT 모드는 그 내부 루프가 없는 모드이므로 같은 전제가 성립하지
> 않는다. 위치/속도 모드에는 내부 속도 루프(`Speed KP/KI`)가 있어 감쇠가 있다.

#### Kd 추가 (Kp = 1 고정)

| Kd | 응답 | 소음 |
|---|---|---|
| 0 | 여러 번 왕복 | 없음 |
| 0.05 | 1회 오버슛 | 미세 진동 |
| **0.1** | **왕복 없이 복귀** ✅ | 미세 진동 + 휘파람 1회 |

#### ⚠ Kd 의 부작용 — 미해결

**Kd 가 0 이 아니면 모터·프레임에 미세 진동이 생긴다.** 엔코더 속도 추정
노이즈에 Kd 가 곱해지는 것이라 원리적으로 없앨 수 없고 줄일 수만 있다.

```
τ = Kp·(오차) + Kd·(v_des − v)
                        ↑ 정지 상태에서도 양자화 때문에 떨린다
```

Kd 0.1 에서 반복해서 밀었을 때 고주파 휘파람("이이이잉")이 **한 번** 발생했다.
감쇠항은 고주파에서 위상 지연 때문에 가진으로 뒤집히므로, 밀어서 에너지를
넣으면 그 모드에 걸릴 수 있다. 이후 재현되지 않았으나 **경계 조건으로 본다.**

이 프로젝트에서는 단순한 소음 문제가 아니다. 진동이 트레이로 전달되면
액체가 흔들리고 트레이 IMU 도 그것을 읽는다. 실장 후 재평가할 것.

발생 시 대처: 시리얼에 `0` 을 쳐서 게인을 즉시 0 으로 (전원 차단보다 빠르다).

## "위이이잉" 은 발진이 아니라 공진 (2026-08-29 판별)

`g1.0` 까지 올린 뒤 간헐적으로 고주파 소음과 진동이 났다. 관찰한 거동.

| 상황 | 소리 |
|---|---|
| 책상에 두고 정지 | 없음 |
| 천천히 기울임 | 없음 |
| **크게 또는 빠르게 반복해서 기울임** | **위이이잉** |
| 다시 내려놓음 | 잠시 뒤 **사라짐** |

**입력이 멈추면 잦아든다**는 것이 핵심이다. 1.75Hz 리밋사이클은 스스로
커지며 멈추지 않았지만, 이것은 때리면 울리고 놔두면 멎는다.

| | 리밋사이클 (이전) | 공진 (지금) |
|---|---|---|
| 입력 없을 때 | 계속 커짐 | 잦아듦 |
| 루프 안정성 | 불안정 | **안정** |

즉 제어 루프는 안정적이고, 루프가 세게 일할 때 구조물이 울리는 것이다.
크게·빠르게 움직일수록 토크 변화가 넓은 주파수 대역을 때려 공진에 걸린다.

**슬로싱 대역과는 멀다.** 소리로 보아 수백 Hz 이고 슬로싱은 2.4Hz 라
100배 이상 떨어져 있다. 액체를 직접 흔들지는 못하므로 제어 성능이 아니라
소음·마모 쪽 문제로 본다.

줄이려면 `CMD_LPF` 를 낮춰 지령의 고주파 성분을 깎으면 되지만 **지연이
늘어난다.** 현재 150~180ms 인데 안티슬로싱 단계에서는 그 지연이 더 해롭다
(슬로싱 주기 420ms 의 36%). 그래서 지금은 두고 **실장 후 재평가**한다.

## 되돌리는 방법 (위치/속도 모드로 복귀)

MIT 모드가 안 맞으면 아래 순서로 원상 복구한다. **두 단계 모두 해야 한다.**

### 1단계 — 드라이버 설정

```
1. CubeMars 닫기
2. ESP32 에 hardware/motor_serial_tools/serial_bridge/serial_bridge.ino 업로드
   (Arduino IDE: Tools → USB CDC On Boot → Enabled)
3. 3핀 시리얼 연결 확인 — GND / 가운데→GPIO17 / 끝→GPIO18
4. 모터 24V ON
5. CubeMars 실행 → COM 포트 → Baud 921600 → OpenPort
6. Set parameters 탭 → ReadParam        ← 반드시 먼저
7. Control settings 의 ControlMode → "2:Pos" 선택
8. WriteParam → "written successfully" 확인
9. 모터 전원 OFF → ON
10. ReadParam 으로 확인
11. 두 모터 모두 반복
```

**Calibrate 는 절대 누르지 말 것.** 교정값이 깨진다.

### 2단계 — 스케치

`모터_수평제어.ino` 를 그대로 업로드한다. 이 파일은 위치/속도 모드용으로
남겨둔 것이며 수정하지 않았다.

### 복구 기준값

전환 전 두 드라이버에서 읽은 값. 이 표와 달라지면 되돌린다.

| 항목 | 값 |
|---|---|
| ControlMode | 2:Pos |
| Position KP / KI | 54 / 0 |
| Speed KP / KI | 0.0037 / 0.0039 (개체별 미세 차이) |
| Damping factor | 4 |
| CurrentBW | 1000 |
| PMAX / VMAX / TMAX | 12.5 / 30 / 10 |
| NPP / GR | 14 / 1 |
| UV / OV / OT | 15 / 32 / 100 |
| Acc / Dec | 2 / -2 |
| Overcurrent | 0.8 |
| CAN Timeout | 0 |
| Master ID | 0x00 |

`hardware/GL60II_모터_설정_가이드.md` 3장에도 원본 백업과 화면 캡처가 있다.

## 시험 구동이 최대 토크를 뿜은 사고 (`fd562bc`)

`motor_test.ino` 의 스윕을 그대로 옮긴 것이 화근이었다.

```cpp
sendPosVel(id, dir ? 0.5f : -0.5f, VEL_LIMIT);   // ±0.5 rad 계단
```

위치/속도 모드에서는 드라이버의 속도 제한이 이 계단을 늘려서 천천히 가게
해줬다. **MIT 에는 그 제한이 없다.** v_des 는 감쇠항의 기준 속도일 뿐이라
목표가 튀면 그 오차에 Kp 를 곱한 토크가 즉시 나간다.

```
τ = Kp × 오차 = 20 × 0.5 rad = 10 N·m   ← TMAX 가 10 이다
```

**최대 토크가 그대로 걸려 기구가 튕겼다.** GAIN 을 낮춰도 소용없었던 이유가
이것이다. 게인이 아니라 목표의 계단이 문제였다.

조치

- 스윕을 삼각파 램프로 변경 (±8°, 20°/s). 진폭·속도를 바꿔도 계단이 될 수 없다
- 끝나면 0° 로 되돌린 뒤 disable — 기울어진 채 방치 금지
- 기본 게인을 Kp 20 → 3 → 최종 1 로 하향
- `kp` 명령이 각도 제한에서의 토크를 함께 출력하도록

> MIT 모드에서 목표를 계단으로 주지 말 것. 이 코드의 모든 목표는
> 슬루 제한을 거쳐 나간다.

## CAN 주소 충돌 — MIT 전환 시 반드시 확인할 것

MIT 로 바꾼 직후 모터가 3바퀴(1080°) 돌며 배선이 끊어졌다. 원인은 게인이
아니라 **주소 충돌**이었다.

```
CAN ID = (제어모드 << 8) | 모터ID

위치/속도(1) : 명령 0x101 / 0x102   피드백 0x000 / 0x001   겹치지 않음
MIT(0)       : 명령 0x001 / 0x002   피드백 0x000 / 0x001   ★ 충돌
```

모터2 의 Master ID 가 `0x01` 이라 그 피드백이 **모터1 의 MIT 명령 주소와
같은 번호**로 나갔다. 모터1 은 그것을 자기 명령으로 해석했고, 피드백
`data[0]`(= ID\|ERR<<4)이 MIT 에서는 `p_des[15:8]` 자리라 목표가 약 −12.3 rad
(−700°)로 읽혔다. Kp 자리에도 쓰레기가 들어갔다.

**조치: 모터2 Master ID `0x01` → `0x11`.**

| | CAN ID | Master ID | 피드백 주소 |
|---|---|---|---|
| 바깥축 | 0x01 | 0x00 | 0x000 |
| 안쪽축 | 0x02 | **0x11** | 0x011 |

`MIT_안전점검.ino` 가 명령 주소로 들어오는 프레임을 세어 경고한다. 무동력
상태에서 `충돌:0` 을 확인한 뒤에 게인을 올릴 것.

> 위치/속도 모드로 되돌려도 Master ID 는 그대로 두면 된다. 명령이 `0x101` /
> `0x102` 라 `0x011` 과 겹치지 않고, 코드는 피드백 프레임의 `data[0] & 0x0F`
> 로 모터를 구분하지 CAN ID 로 구분하지 않는다.
