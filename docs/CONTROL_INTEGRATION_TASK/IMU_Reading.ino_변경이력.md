## 1. 최초 작성 (`6f8df5f`)

기존 서보 구조 코드에서 상보 필터, 자이로 영점 캘리브레이션, 100Hz 루프 구조를
가져오고 센서와 핀을 교체.

### 핀 변경

기존 코드의 SPI 핀은 ESP32-S3 에서 사용 불가.

| 기존 | 문제 | 변경 |
|---|---|---|
| `SDI_PIN = 23` | **S3 에 GPIO 22~25 자체가 없음** | `11` (MOSI) |
| `SDO_PIN = 19` | USB D− | `13` (MISO) |
| `SCK_PIN = 18` | UART 로 재배정됨 | `12` (SCK) |
| `CS_ACTIVE = 5` | CAN 으로 재배정됨 | `10` |

IMU 보드 라벨이 I2C 표기(`SDA`/`SCL`/`SDO`)지만 SPI 4-wire 에서는
`SDA` = MOSI, `SCL` = SCK, `SDO` = MISO 로 동작.

### 센서 변경 (BMI160 → LSM6DSOX)

| 항목 | BMI160 | LSM6DSOX |
|---|---|---|
| 데이터 주소 | `0x0C` | `0x22` |
| WHO_AM_I | `0x00` → `0xD1` | `0x0F` → `0x6C` |
| **`GYRO_LSB`** | 16.4 | **14.286** |
| 전원 시퀀스 | `0x7E` 커맨드 반복 | `CTRL3_C` 리셋 1회 |

> `GYRO_LSB` 주의. 16.4 는 ICM/MPU 계열 값이고 LSM6DSOX 는 70 mdps/LSB 라
> 14.286 이다. 안 바꾸면 에러 없이 각속도가 15% 작게 나온다.

바이트 순서(리틀엔디안, 자이로 먼저)는 BMI160 과 동일해 파싱 로직 재사용.

### 이때 추가한 방어 로직

디버깅 과정(아래 2절)에서 확인된 문제에 대응해 3가지를 함께 넣었다.

1. **부팅 진단** `dumpDiag()` — WHO_AM_I / CTRL 레지스터 / raw 12바이트 덤프
2. **리셋 감지 및 복구** — `CTRL1_XL` 이 변하면 재초기화
3. **`|a|` 검사** — 1g 를 벗어난 샘플은 가속도 보정 제외

## 2. 디버깅 이력

### 증상 1 — `pitch_acc` 가 `0.00` / `35.26` 두 값만 출력

```
pitch:6.82,pitch_acc:35.26,roll:6.20,roll_acc:-35.26
pitch:17.57,pitch_acc:0.00,roll:14.90,roll_acc:0.00
```

`arctan(1/√2) = 35.264°` 이므로 **ax = ay = az** 일 때만 나오는 값.
포화가 아니라 **데이터가 아예 안 들어오는 상태**였다.

```cpp
pitch_acc = atan2(ay, sqrt(ax² + az²))    // ax=ay=az=k 면 항상 35.26°
```

각도가 365° 까지 발산한 것은 원인이 아니라 결과였다. 가속도계가 죽으면
상보 필터가 절대 기준을 잃고 순수 자이로 적분이 되기 때문.

→ 배선 수정 후 해결. 이 판별을 자동화하기 위해 `dumpDiag()` 추가.

### 증상 2 — 잘 되다가 갑자기 깨짐

```
pitch:-52.50,pitch_acc:-52.49    ← 정지 상태, 0.01° 일치
pitch:-52.52,pitch_acc:-52.98    ← 여기까지 정상
pitch:-51.65,pitch_acc:-48.79    ← 움직이기 시작
pitch:-54.04,pitch_acc:-72.09    ← 즉시 깨짐
```

정지 상태에서는 완벽했고 **움직인 순간부터** 깨졌다. 설정 문제가 아닌 간헐적 오류.
`pitch_acc` 가 정확히 `0.00` 인 구간은 센서 리셋(파워다운) 신호.

→ 리셋 감지 및 복구 로직이 이 문제의 핵심 대응이었다. 이전에는 리셋 한 번에
센서가 파워다운으로 영구 방치되어 세션이 죽었다 (증상 1의 365° 발산이 그것).
복구 로직 추가 후 자가 회복되어 장시간 안정 동작.

### 증상 3 — 거부 카운터로 판단이 안 됨

```
[stat] reset:1  bit_err:1999 / 12323 (16.2%)
```

통신 오류인지 실제 움직임인지 구분 불가. 카운터가 두 원인을 섞어 세고 있었다.

또한 거부 **개수**보다 **연속 길이**가 중요하다는 점이 반영되지 않았다.
샘플을 버리면 그 순간 자이로 단독 적분이 되는데, 흩어져 있으면 무해하고
뭉치면 각도가 틀어진다. (1샘플 = 0.01초)

## 3. 연속 구간 추적 추가 (`369ac00`)

### ① 연속 무보정 구간 추적

```cpp
if (acc_ok) {
  rej_run = 0;
} else {
  if (++rej_run > rej_run_max) rej_run_max = rej_run;
}
```

| 최대연속 | 자이로 단독 시간 | 판정 |
|---|---|---|
| ≤ 5 | 0.05초 | 무해 |
| ~50 | 0.5초 | 드리프트 발생 |

### ② 파워다운 즉시 감지

기존에는 `CTRL1_XL` 을 1초 주기로만 확인해 리셋 시 최대 1초간 방치됐다.
`|a|` 가 0 에 가까우면 파워다운 신호이므로 그 자리에서 복구하도록 변경.

```cpp
if (a_mag < ACC_MAG_DEAD && readReg(REG_CTRL1_XL) != CTRL1_XL_VAL) {
  err_reset++;
  configSensor();
}
```

## 4. 1차 벤치 테스트 (하드 컷 / ±2g)

| 조건 | 결과 | 판정 |
|---|---|---|
| **정지** | 오류 **0 / 304** | 배선 정상 ✅ |
| 가볍게 움직임 | 최대연속 7~8 (0.08초) | 무해 ✅ |
| 격하게 흔듦 | 최대연속 **44** (0.44초), `\|a\|` **2.77g** | 문제 ❌ |

**정지 시 오류 0** — 이전의 16% 는 전부 실제 움직임이었고 하드웨어는 정상이었다.

격한 동작에서 두 가지 문제 확인.

1. `|a| = 2.77g` → **±2g 범위 포화**
2. 0.44초 연속 무보정 → 자이로 단독 적분으로 `roll` 이 -103° 까지 붕괴

로봇 주행 시 출발·정지에서 동일 상황이 발생하므로 제어 진입 전 수정 필요.

> 로그 해석 주의점도 발견. `최대연속` 이 부팅 이후 최고 기록이라 한 번 올라가면
> 안 내려가는데, 이를 "지금도 계속 빠지는 중" 으로 오해할 수 있었다.
> `bit_err` 가 122 에서 멈춰 있었던 것이 실제로는 정상이라는 증거였다.

## 5. 신뢰도 가중 전환 (`90e3c8c`)

### ① 측정 범위 ±2g → ±4g

```cpp
#define CTRL1_XL_VAL  0x68      // ±4g  (기존 0x60 = ±2g)
const float G_LSB = 8192.0;     // 기존 16384.0
```

### ② 하드 컷 → 신뢰도 가중

버리면 연속 구간이 생기므로, **버리지 않고 비중만 줄인다.**

```cpp
float dev   = fabsf(a_mag - 1.0f);
float trust = constrain(1.0f - dev / ACC_TRUST_FALLOFF, 0.0f, 1.0f);
float alpha = 1.0f - (1.0f - alpha_cf) * trust;

pitch_filtered = alpha*(pitch_filtered + rate_pitch*dt) + (1.0f-alpha)*pitch_acc;
```

| `\|a\|` | trust | 동작 |
|---|---|---|
| 1.00g | 1.00 | 평소대로 보정 |
| 1.25g | 0.50 | 절반만 반영 |
| 1.50g+ | 0.00 | 자이로 단독 |

가속 중에도 가속도계가 완전히 입을 다물지 않아 드리프트 누적이 줄어든다.
이 로직은 통신 오류 차단과 **선형 가속으로 인한 기울기 오염 방지**를 동시에
수행하므로 짐벌 제어 진입 후에도 유지할 것.

### ③ 진단 로그를 구간 기준으로

누적 표시는 한 번 튄 값이 계속 남아 오해를 만들었다. 직전 1초 구간 기준으로
바꾸고, 연속 길이는 최근/전체를 함께 표시.

```
[stat] reset:0  무보정:0/101  연속:0최근/44전체  |a|=1.01 trust=1.00
```

## 6. 2차 벤치 테스트 (신뢰도 가중 / ±4g)

### 결과 — 전 항목 개선 확인

| 조건 | 1차 (하드 컷 / ±2g) | 2차 (가중 / ±4g) | 개선 |
|---|---|---|---|
| 정지 — `pitch_acc` 흔들림 | 0.15° | **0.25°** | 동등 (정상) |
| 가볍게 기울임 — 최대연속 | 14 | **0** | 완전 해소 |
| 격하게 흔듦 — 최대연속 | 44 (0.44초) | **12 (0.12초)** | **3.7배 단축** |
| 격하게 흔듦 — `\|a\|` | 2.77g (포화) | **3.21g (포화 없음)** | 해소 |

가볍게 기울이는 구간에서 `trust` 가 0.82~0.90 으로 부드럽게 내려가며
**한 샘플도 버리지 않았다.** 격한 동작에서도 무보정 구간이 12샘플 이하로
짧게 끊겨 이전처럼 각도가 -103° 로 붕괴하지 않았다.

### 정지 상태 노이즈 원인 = 손 떨림 (센서를 들고 있었음)

정지 상태 `pitch_acc` 흔들림 폭 비교.

| 조건 | 흔들림 폭 | 통신 오류 |
|---|---|---|
| 센서를 손에 들고 정지 | **9.56°** | 0 |
| 센서를 바닥에 내려놓고 정지 | **0.25°** | 0 |

통신 오류는 양쪽 다 0 이므로 데이터는 정상이었고, **센서가 실제로 흔들린 것**이다.
원인은 손 떨림. 가만히 들고 있어도 미세 진동이 그대로 측정된다.

> **진동은 신뢰도 가중으로 걸러지지 않는다.**
> 옆방향 진동 0.087g 는 각도를 5° 흔들지만 크기는
> `√(1² + 0.087²) = 1.004g` 로 거의 그대로라 `|a|` 검사를 통과한다.
>
> 진동원이 손이든 모터든 동일하게 적용되는 특성이므로, 실장 후 진동이
> 확인되면 방진 마운트(고무 부싱·실리콘 그로밋)를 검토할 것.

> **초기 오판 기록.** 이 노이즈를 처음에 모터 진동으로 결론냈으나 오류였다.
> 노이즈가 사라진 측정에서 모터 전원이 꺼져 있었던 것은 사실이나, 같은 측정에서
> 센서를 손에서 내려놓은 변화가 함께 있었다. 교란 변수가 둘인 비교를 근거로
> 인과를 단정한 것. **모터 진동의 영향은 아직 측정된 바 없다.**

### 잔여 항목 — 중력 스케일 편차

```
|a|=0.97 trust=0.94
```

정지 상태인데 `trust` 가 1.00 이 아니었다. 가속도계가 1g 를 0.97g 로 3% 낮게
읽는 개체 편차 때문. 센서 스펙 범위 내지만 두 가지 부작용이 있다.

- 정지 시에도 가속도계를 94% 만 반영
- 신뢰도 감쇠 기준이 실제 1g 가 아닌 0.97g 에서 출발

→ 아래 7절에서 정규화로 해결.

## 7. 중력 스케일 정규화 (`b7e41eb`)

부팅 캘리브레이션에서 자이로 영점을 잴 때 정지 상태 `|a|` 도 함께 측정해
그 값으로 정규화한다.

```cpp
// setup() — 200회 루프에서 함께 누적
smag += sqrtf(fax*fax + fay*fay + faz*faz) / G_LSB;
...
float measured = smag / 200.0;
if (measured > 0.5f && measured < 1.5f) g_scale = measured;   // 이상값이면 생략

// loop()
float a_mag = sqrtf(...) / G_LSB / g_scale;    // 정지 시 정확히 1.000
```

캘리브레이션 중 센서를 움직이면 엉뚱한 값이 잡히므로 0.5~1.5 범위를
벗어나면 정규화를 건너뛰고 `g_scale = 1.0` 을 유지한다.

부팅 로그에 측정값이 찍힌다.

```
gyro bias  x:-12.3  y:5.7   g_scale:0.9712
```

## 8. 3차 벤치 테스트 — 정규화 검증 및 최종 확인

### 정지 상태에서 `trust = 1.00` 달성

```
[stat] reset:0  무보정:0/101  연속:0최근/0전체  |a|=1.00 trust=1.00
```

| 항목 | 정규화 전 | 정규화 후 |
|---|---|---|
| `\|a\|` | 0.97 | **1.00** |
| `trust` | 0.94 | **1.00** |
| `pitch` 변동 | — | **0.03°** (67.92 ~ 67.95) |
| `pitch_acc` 흔들림 | 0.25° | 0.34° |

가속도계를 100% 활용하게 됐고 신뢰도 감쇠 기준도 실제 1g 에서 출발한다.

### 축·부호 검증 통과

자이로 부호가 반대면 필터가 가속도계와 반대로 튀거나 발산하는데,
움직이는 동안 두 값이 같은 방향으로 움직이고 정지 시 다시 일치했다.

```
pitch:10.82,pitch_acc:15.44     ← 같이 상승
pitch:62.05,pitch_acc:61.64
pitch:67.92,pitch_acc:67.91     ← 정지 후 일치
```

roll 도 `-27 → +9` / `roll_acc` `-21 → +3.8` 로 동일. **두 축 모두 정상.**

### 전체 추이

| 조건 | 1차 (하드컷/±2g) | 2차 (가중/±4g) | 3차 (+정규화) |
|---|---|---|---|
| 정지 `trust` | — | 0.94 | **1.00** |
| 조금씩 — 최대연속 | 14 | 0 | 3 (0.03초) |
| 많이 — 최대연속 | **44** (0.44초) | 12 | **14** (0.14초) |

3차의 14는 2차의 12와 흔든 강도 차이 수준이며, 1차의 44 대비 약 1/3 로
안정화된 상태가 유지된다.

**IMU 읽기 단계는 검증 완료.** 이후 작업은 실장(방진·배선)과 제어 연동이다.
