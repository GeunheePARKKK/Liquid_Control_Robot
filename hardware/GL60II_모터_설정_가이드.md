# GL60II 모터 — ESP32 연결 및 설정 가이드

작업일: 2026-08-23 · 상태: **배선 완료 + CAN ID 변경(파라미터 설정) 완료**

간단한 CAN 배선만 필요하면 [`모터_ESP32연결.md`](모터_ESP32연결.md) 를 본다.
이 문서는 거기서 한 걸음 더 나가서, **드라이버 파라미터(CAN ID 등)를 직접 바꿔야 할 때**
필요한 시리얼 배선·설정·절차와, 그 과정에서 겪은 문제들을 정리한 것이다.

- CAN 프로토콜과 실제 동작 코드: [`hardware/MOTOR_HANDOFF.md`](MOTOR_HANDOFF.md)
- 진단용 스케치: `hardware/motor_serial_tools/`

## 0. ⚠️ 먼저 확인하세요 — 가장 많이 걸리는 함정 두 가지

시리얼이 안 뜬다고 배선을 다시 뜯기 전에, 이 두 개부터 확인한다.
아래를 안 보고 몇 시간을 배선 탓으로 돌린 적이 있어서 맨 위에 적어둔다.

### ① 이 ESP32-S3 보드는 USB-C 단자가 **두 개**다

보드에 `USB`, `COM` 이라고 적힌 USB-C 포트가 각각 따로 있다. 물리적으로 완전히
다른 경로다 (하나는 ESP32 칩의 네이티브 USB, 다른 하나는 온보드 USB-시리얼 변환칩을
거친다).

| CDC 설정 (Tools → USB CDC On Boot) | 꽂아야 하는 단자 |
|---|---|
| **Enabled** | 반드시 **`USB`** 라고 적힌 단자 |
| Disabled | `COM` 이라고 적힌 단자 |

**엇갈리면 화면이 완전히 텅 빈다.** 배선(TX/RX, GND, 풀다운 등)은 전부 정상인데 그냥
"연결은 됐지만 코드가 보는 포트가 아닌" 상태가 되고, 증상만 보면 배선 불량과 구분이 안 된다.
시리얼이 안 뜨면 배선보다 **이 단자 매칭을 제일 먼저** 확인한다.

### ② 드라이버는 전원만 켠다고 먼저 말을 걸지 않는다

매뉴얼 p17에는 "전원을 인가하면 시리얼 포트가 정보를 출력한다"고 적혀 있지만,
**실제로는 상위 SW(CubeMars)가 먼저 질의를 보내야 응답이 온다.** 드라이버가 자발적으로
보내는 데이터는 없다. 그래서 "포트 열고 → 전원 켜고 → 로그 뜨는지 기다리기"는
애초에 성립하지 않는 테스트다. 확인하려면 상위 SW로 `ReadParam`을 눌러야 한다 (4장 참고).

이 두 가지가 겹치면 "배선 다 맞는데 아무것도 안 뜬다"는 증상이 나오고, 케이블 연속성
체크·GND 교차검증·TX/RX 스왑·풀다운 테스트를 아무리 해도 원인이 안 잡힌다. 그 테스트들
자체가 틀린 게 아니라, 순서상 **① 단자 확인이 먼저**여야 한다는 뜻이다.

## 1. 시리얼 3핀 배선 (파라미터 설정용, 별도 케이블 필요)

CAN/전원 배선은 [`모터_ESP32연결.md`](모터_ESP32연결.md) 를 그대로 따르고, 거기에
아래 시리얼 3핀만 추가로 연결한다. 드라이버에는 커넥터가 두 개이고, **둘 다 동시에
연결한 상태로 작업했다.**

| 드라이버 3핀 | ESP32-S3 |
|---|---|
| GND | GND |
| **가운데 핀** | **GPIO17** |
| **끝 핀** | **GPIO18** |

> **매뉴얼(p7)의 핀 순서(1=GND, 2=TX, 3=RX)와 실제가 반대였다.**
> 처음에 GND 다음 핀을 GPIO18에 연결했을 때는 통신이 안 됐고,
> GPIO17로 바꾸자 바로 됐다. 위 조합을 기준으로 삼는다.

이 커넥터는 **CJT A1257, 1.25mm 간격**이라 모터에 딸려온 케이블에는 없다.
`GH1.25 3핀 케이블` (JST GH 호환) 을 별도로 구해야 한다. 브레드보드용 흔한
듀폰 점퍼(2.54mm)는 간격이 두 배라 안 들어간다.

### 배선 시 주의 (노이즈)

드라이버 PWM 노이즈(40kHz, 25µs 주기)가 시리얼 선에 유도되어 통신을 방해할 수 있다.

- 3핀 시리얼 선을 모터 3상 선·24V 전원선에서 멀리 뗄 것
- 신호선을 GND 선과 꼬아서(트위스트) 배선할 것
- 선 길이를 최소화할 것

### 전체 배선도 (실제로 동작한 구성)

```
  전원공급기 24V (전류제한 2A 이상)
    |

    |                   |         |                               |

    |                   |         |      빨강 = 전원 +             |

    |                   |         |      흰색 = CAN_H  ---------+  |
```

## 4. 상위 SW 조작 순서 (파라미터 변경 재현용)

```
1. Arduino IDE 시리얼 모니터 닫기 / IDE 닫기
2. ESP32 에 serial_bridge.ino 업로드 (MOTOR_BAUD 921600)
3. 모터 24V 전원 ON        <- 반드시 켜야 한다. 안 켜면 무조건 시간 초과
4. CubeMars.exe 실행
5. Serial Port 구역: 포트 선택, Baud 921600 확인 -> OpenPort
6. "Set parameters" 탭 -> "ReadParam"           <- 반드시 먼저 읽어야 한다 (0-② 참고)
7. 값 수정 (예: CAN ID)
8. "WriteParam"
9. 모터 전원 OFF -> ON
10. "ReadParam" 으로 변경 확인
```

상위 SW: 제조사 배포판 `gl-ii-upper-computer-v1-0.zip` 을 풀면 `CubeMars.exe` 하나가 나온다.
별도 설치 없이 실행된다. 서명이 없어 Windows SmartScreen 경고가 뜨면
"추가 정보" → "실행" 으로 넘기면 된다. (리포에는 포함하지 않았다 — 제조사 배포물)

### 절대 누르지 말 것

| 금지 | 이유 |
|---|---|
| **Calibrate** | 모터가 회전하며 센서 교정을 다시 한다. 드라이버 보드 재장착·3상 배선 변경·펌웨어 업데이트 시에만 필요(매뉴얼 4.3). 기존 교정값이 깨진다 |
| **Upgrade (펌웨어)** | 실패하면 드라이버가 벽돌된다 |
| CAN ID 외 다른 파라미터 | 위 3장 백업값과 달라지면 원인 추적이 어려워진다 |

### COM 포트는 한 프로그램만 독점한다

**Arduino IDE 시리얼 모니터가 열려 있으면 CubeMars 가 포트를 못 연다.**
"포트를 먼저 열어라" 메시지가 뜨면 이것부터 확인한다.
업로드할 때는 반대로 CubeMars 를 닫아야 한다.

## 5. ⚠ VMAX = 30 — 코드 수정이 필요하다

[`hardware/MOTOR_HANDOFF.md`](MOTOR_HANDOFF.md) 와 매뉴얼은 속도 범위를 **±200 rad/s** 로
적고 있지만, **이 드라이버의 실제 VMAX 는 30** 이다. 매뉴얼 p48에도 명시돼 있다.

> Pos, Vel, Torque 는 각각 ±12.5, ±200, ±10 으로 프리셋되어 있으며, 이 세
> 파라미터는 모터의 실제 파라미터에 따라 조정할 수 있다. **제어 명령을 보낼 때는
> 설정된 값과 일치시키는 것이 필수적이다.**

### 영향받는 곳

**① 피드백 속도 해석** — 12bit 값을 ±VMAX 로 환산해야 한다

```cpp
// 틀림 (±200 가정)
motor_spd = uint_to_float(spd_int, -200.0f, 200.0f, 12);

// 맞음 (이 드라이버는 VMAX=30)
motor_spd = uint_to_float(spd_int, -30.0f, 30.0f, 12);
```

**② 위치/속도 명령의 속도 제한** — 상한이 30 rad/s 다. 그 이상 보내도 잘린다.

**③ 위치(±12.5)와 토크(±10)는 매뉴얼과 같으므로 그대로 두면 된다.**

`Config.h` 에 상수로 넣고 하드코딩하지 말 것.

## 6. 추가로 알아낸 사실 (같은 삽질 반복 금지)

### S-link 는 필요 없다

S-link 는 USB를 시리얼+CAN 으로 나눠주는 어댑터일 뿐이다(5V, 39×29×10mm).
**파라미터 읽기/쓰기는 시리얼로만 이루어지므로** ESP32 를 USB-시리얼 중계기로
쓰면 대체된다. CAN 연결은 PC에서 모터를 직접 돌리는 "Test" 화면에만 필요하고,
우리는 ESP32 로 돌리니 불필요하다.

근거: 제어 모드는 CAN으로 바꿀 수 없는데(매뉴얼 p41의 CAN 명령은 4개뿐),
CAN ID 가 제어 모드와 같은 `Drive parameters` 그룹에 있다 → 이 화면은 시리얼 경로다.

### CAN 으로는 ID / 제어모드를 바꿀 수 없다

매뉴얼 p41 Universal CAN 명령은 4개뿐이다.

| 명령 | 데이터 |
|---|---|
| Enable | `FF FF FF FF FF FF FF FC` |
| Disable | `FF FF FF FF FF FF FF FD` |
| 현재 위치 영점 | `FF FF FF FF FF FF FF FE` |
| 에러 해제 | `FF FF FF FF FF FF FF FB` |

ID·모드는 드라이버 플래시에 저장되고 상위 SW(시리얼)로만 쓴다.

### baud 는 듣기만 해서 알아낼 수 없다

`serial_probe` 로 8개 baud 전부 시도 → 어디서도 읽을 수 있는 데이터 없음.
`baud_measure` 로 비트폭 측정 → 값이 매번 다름(1000000, 500000, 41666...) = 노이즈였다.
25µs(40kHz) 성분이 반복 등장 → 드라이버 PWM 스위칭 노이즈가 선에 유도된 것.

**결론: baud 는 상위 SW의 `Serial Port` 설정 칸에서 눈으로 확인하는 게 정답이었다.**
(이것도 0-② "드라이버는 먼저 말하지 않는다"의 연장선이다.)

## 7. 남은 작업

- [ ] **모터에 라벨 붙이기** — CAN ID 0x02 로 바꾼 모터에 "2번" 표시.
      안 하면 나중에 어느 게 어느 건지 알 수 없다
- [ ] 두 번째 모터는 0x01 그대로 (바꿀 필요 없음)
- [ ] 두 모터를 같은 CAN 버스에 연결하고 개별 제어 확인
      `hardware/MOTOR_HANDOFF.md` 3장의 최소 동작 코드에서 `MOTOR_ID` 를
      `0x01` / `0x02` 로 바꿔가며 한쪽만 움직이는지 확인
- [ ] `Gimbal.cpp` 구현 시 **VMAX = 30** 반영 (5장)
- [ ] 시리얼 배선 노이즈 대책 (1장)
- [ ] `hardware/MOTOR_HANDOFF.md` 의 속도 범위 ±200 → ±30 정정

### 개별 제어 확인 방법

```
모터 #1 (ID 0x01) -> CAN ID 0x101
모터 #2 (ID 0x02) -> CAN ID 0x102

피드백은 둘 다 ID 0x0 로 오지만 Data[0] 하위 4비트가 모터 ID 라서 구분된다.
따라서 Master ID 는 둘 다 0x00 으로 둬도 된다.
```

## 부록: 사용한 진단 스케치

`hardware/motor_serial_tools/` 에 있다. 나중에 같은 문제가 생기면 순서대로 쓰면 된다.

| 스케치 | 용도 |
|---|---|
| `serial_bridge` | **PC ↔ 모터 중계 (고정 baud 921600). 실제로 성공한 것** |
| `pin_check` | 핀이 실제로 연결됐는지 판정 (풀업/풀다운 비교). UART 안 씀. 배선이 의심될 때 최단 판정 도구 |

### 만들었지만 리포에 포함하지 않은 것 (기록)

`serial_probe`, `serial_probe2`, `baud_measure`, `serial_bridge_auto` 네 개는
**baud 와 TX 핀을 알아내려고** 만든 도구다. 두 값이 확정됐으므로 제외했다.

특히 `serial_probe` / `baud_measure` 계열 — 드라이버가 스스로 보내는 출력을 잡아
baud 를 역산하는 접근 — 은 **이 드라이버에서는 원리적으로 불가능하다** (6장 참고).
**같은 시도를 반복하지 말 것.**

## 부록 B: 배경 개념 (처음 보는 사람용)

### 이 모터는 "말을 알아듣는 모터"다

보통 모터는 전선에 전기를 흘리면 돕니다. GL60II는 모터 뒤에 **작은 컴퓨터 보드(드라이버)**
가 붙어 있어서, 전기를 그냥 흘리는 게 아니라 **문장으로 명령을 보내야** 합니다.

> "3라디안 위치로 가라, 속도는 1rad/s로"

이걸 전기 신호로 만들어 보내면 드라이버가 알아듣고 알아서 그 각도까지 돌립니다.

### 대화 통로가 두 개 있다

드라이버 보드에 **꽂는 구멍(= 커넥터)이 두 개** 있습니다.

```
        +------------------------------+
        |    GL60II 드라이버 보드        |
        |                              |
        |   [#] (1)번 구멍 - 작은 3핀   |  ← 설정용 (시리얼)
        |                              |
        |   [#] (2)번 구멍 - 큰 XT30    |  ← 전원 + 조종용 (CAN)
        +------------------------------+
```

| 번호 | 커넥터 | 핀 구성 | 용도 |
|---|---|---|---|
| (1) | 작은 3핀 (CJT A1257, 1.25mm 간격) | GND / TX / RX | **설정** 변경 |
| (2) | 큰 XT30(2+2) | 전원+ / 전원− / CAN_H / CAN_L | 전원 공급 + **조종** |

### CAN = 단체 카톡방

CAN은 **전선 딱 두 가닥을 여러 장치가 공유**하는 통신입니다.

```
   ESP32 --+---------+---------+---- 전선 2가닥 (CAN_H, CAN_L)
           |         |         |
         모터1     모터2    (나중에 더)
```

전선이 하나뿐이니 메시지 앞에 **이름표(ID)** 를 붙입니다. 모터들은 흐르는 메시지를
전부 듣지만 **자기 이름표가 붙은 것만 실행**합니다.
단체 카톡방에서 "@철수 이거 해줘" 하면 철수만 반응하는 것과 같습니다.

장점: 모터가 10개여도 전선은 2가닥이면 됩니다.

### 시리얼(UART) = 1:1 면담

시리얼은 **장치 두 개를 일대일로 직접 연결**하는 방식입니다. 이름표 개념이 없고,
선으로 연결된 상대와만 대화합니다.

우리 경우엔 **PC와 모터 드라이버를 직접 연결**할 때 씁니다. ESP32는 여기 안 끼어듭니다.

### 용도 정리

| | CAN — (2)번 구멍 | 시리얼 — (1)번 구멍 |
|---|---|---|
| 하는 일 | **조종** "움직여라" | **설정** "이름을 2번으로 바꿔라" |
| 연결 | ESP32 ↔ 모터 | PC ↔ 모터 |
| 사용 시점 | 로봇 동작 중 계속 | 처음 한 번, 설정할 때만 |

### 헷갈리는 용어 두 개

**TWAI** = ESP32 칩 안에 들어있는 **CAN 통신 담당 회로의 이름**.
그냥 "ESP32의 CAN 기능"으로 읽으면 됩니다. (Espressif가 상표 문제로 CAN이라 안 부릅니다)

**트랜시버 (SN65HVD230)** = **통역사**.
ESP32는 3.3V로 신호를 만드는데 CAN 전선 위의 신호는 생김새가 다릅니다(두 선의
전압 차이로 0/1 표현). 그 사이를 변환해주는 작은 부품입니다.

```
  ESP32 --(3.3V 신호)-- 트랜시버 --(CAN 신호)-- 모터
        내부 언어           통역          외부 언어
```

### 커넥터 규격 주의

(1)번 구멍은 **1.25mm 간격**입니다. 브레드보드용 흔한 점퍼선(2.54mm)은
**간격이 두 배라서 안 들어갑니다.** 이거 모르고 시도하다 포기하는 경우가 많습니다.

```
   1.25mm 간격        2.54mm 간격
   ###                #  #  #
   ↑ 드라이버          ↑ 흔한 듀폰 점퍼
```

검색어: `GH1.25 3핀 케이블` / `1.25mm 3P 하네스` / `JST GH 3핀`
(CJT A1257은 JST GH와 호환됩니다. 디바이스마트, 엘레파츠 등에서 판매)
