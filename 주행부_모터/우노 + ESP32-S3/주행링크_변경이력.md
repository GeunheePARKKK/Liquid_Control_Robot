## 2026-10-24 21:41 — 실물 배선 반영 · 워치독 버그 수정 (커밋 4b0fc68)

실제 로봇에 올려 보며 고친 것. 우노·ESP32 둘 다 재업로드 필요.

- `uno_drive_link.ino`
  - 핀을 예전 2WD 코드와 동일하게: 앞왼 D6/D4 (전진 DIR LOW, `L_INVERT 1`), 앞오른 D9/D8 (전진 DIR HIGH).
    README 표의 D5/A0, D9/A2 는 실물과 달랐음. 뒷바퀴 채널 0 고정 코드 삭제.
  - 엔코더를 예전 코드처럼 B상만: FL D3 인터럽트, FR D7 폴링. 부호는 현재 PWM 방향.
  - ESP32 링크 핀 A4/A5 → **D10(S10) RX / D11(S11) TX**. A5 는 예전 시작 스위치 자리.
  - 링크 9600 baud. 우노 → ESP32 상태 전송(`E`)은 `SEND_STATUS 0` 으로 기본 끔
    (SoftwareSerial 은 보내는 동안 수신이 막혀 M 명령이 깨짐). 링크 명령 응답은 USB 로만.
  - **버그 수정**: `loop()` 위에서 읽은 `now` 로 워치독을 판정해, 명령 처리 중 1ms 지나면
    `now - lastCmdMs` 가 뒤집혀 매 루프 정지/재시작 → 바퀴가 끊김. 입력 처리 뒤 `now = millis()` 다시 읽음.
  - 테스트 PWM 100 → 150.
- `esp32_drive_wifi.ino`: 링크 9600 baud, 주석(핀 S10/S11, COM 포트 + USB CDC On Boot = Disabled).
- `README.md`: 배선표(GPIO17→S10, GND→G, 5V←외부 5V; S11 분압은 선택), 우노 핀표, 순서 갱신.
- 확인: `w` 3초 주행 끊김 없음, 우노 모니터 `[link] up` 한 번만.
