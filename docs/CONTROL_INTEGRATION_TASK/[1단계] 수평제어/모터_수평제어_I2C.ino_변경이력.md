## 왜 I2C 로 바꿨나

### SPI 가 죽었다

베이스 IMU 가 SPI 로 `WHO_AM_I` 에 `0x00` 만 돌려주기 시작했다. 오전에는 같은
보드·같은 코드로 `0x6C` 가 정상으로 나오던 센서였다.

배제한 것들 — **전부 정상이었다.**

| 확인 | 방법 | 결과 |
|---|---|---|
| VIN 전원 | 보드 전원등 점등 | 정상 |
| GND | 도통 | 정상 |
| SDA (GPIO11) | 도통 | 0Ω |
| SCL (GPIO12) | 도통 | 0Ω |
| CS (GPIO10) | 도통 | 0Ω |
| SDO 풀다운 | SDO↔GND 저항 | 10kΩ (정상값) |
| CS 핀 위치 | `../[0단계] 센서 및 모터 설정/IMU_핀찾기.ino` 로 13핀 스캔 | 전부 `0x00` |
| 브레드보드 | 통째로 교체 | 변화 없음 |
| ESP32 | 오전에 되던 그 보드 | — |

### 그런데 I2C 로는 응답했다

`../[0단계] 센서 및 모터 설정/IMU_I2C확인.ino` 로 확인.

```
응답 주소: 0x6A
0x6A → WHO_AM_I 0x6C   ★ 칩 살아있음
판정: 칩 정상. SPI 경로만 문제다.
```

**칩은 멀쩡하고 SPI 인터페이스만 죽었다.** I2C 와 SPI 는 같은 다이에 있지만
입력단 회로가 일부 다르므로 한쪽만 상할 수 있다.

원인은 그 전에 몇 시간 이어진 **VIN 접촉 불량**으로 보인다. 전원이 빠르게
끊겼다 붙었다 하며 브라운아웃 구간을 반복해서 지나갔다.

> **오진 기록.** 이 시점에 칩 전체가 죽은 것으로 결론냈으나 틀렸다.
> I2C 를 시도해 보자는 판단이 나온 뒤에야 살아있음이 확인됐다.
> SPI 가 안 되면 I2C 를 먼저 시도할 것. 5분이면 갈린다.

### 성능은 문제없다

| | SPI | I2C |
|---|---|---|
| 속도 | 1 MHz | 400 kHz |
| 12바이트 읽기 | ~0.1 ms | **~0.3 ms** |
| 제어 주기 | 10 ms | 10 ms |

10ms 주기에 0.3ms 면 여유가 충분하다.

### 오히려 유리한 점 — 회전부 배선

트레이 IMU 는 짐벌 위에서 계속 회전한다. 그쪽으로 가는 선은 적을수록 좋다.

| | SPI | I2C |
|---|---|---|
| 공유 가능한 선 | SDA·SCL·SDO | SDA·SCL |
| IMU 마다 따로 필요한 선 | **CS** | 없음 (주소로 구분) |

```
베이스 IMU : SDO → GND → 주소 0x6A
트레이 IMU : SDO → 3V3 → 주소 0x6B
```

두 IMU 가 같은 두 선만 쓰면 되므로 **회전부로 가는 선이 하나 줄어든다.**

## 배선

```
IMU        ESP32-S3      비고
---        --------      ----
VIN   →    3V3
GND   →    GND
SDA   →    GPIO 11
SCL   →    GPIO 12
CS    →    3V3           ★ HIGH 고정 — 이래야 I2C 모드
SDO   →    GND           ★ 주소 하위비트 (GND=0x6A, 3V3=0x6B)
```

**GPIO10·13 은 쓰지 않는다.** SPI 판에서 CS·MISO 로 쓰던 핀이다.

풀업은 브레이크아웃 내장으로 동작했다. 선이 길어지면 4.7kΩ 을 SDA·SCL
각각에서 3V3 으로 달 것.

## 코드 차이

SPI 판에서 **센서 읽기 계층만** 바뀌었다.

| 항목 | SPI 판 | I2C 판 |
|---|---|---|
| 읽기 | `SPI.transfer(reg \| 0x80)` | `Wire` — MSB 규칙 없음 |
| 쓰기 | `SPI.transfer(reg & 0x7F)` | `Wire.write(reg, val)` |
| CS | GPIO10 토글 | 3V3 고정 (코드가 건드리지 않음) |
| 연속 읽기 | 12바이트 버스트 | repeated start 후 12바이트 |
| 오류 계수 | 없음 | `i2c_err` 추가 |

레지스터 주소·설정값(`CTRL1_XL 0x68` 등)은 인터페이스와 무관하게 동일하다.
`IF_INC`(CTRL3_C 의 `0x44`)가 1 이어야 연속 읽기에서 주소가 자동 증가하는 것도 같다.

**그대로 유지한 것** — 제어식, 게인(Kp 1 / Kd 0.1), 상보필터, 신뢰도 가중,
중력 정규화, 폭주 차단(±50°), 피드백 두절 감지, 시리얼 명령, MIT 모드 CAN 전송.

### 추가된 진단

```
[stat] ARMED ... 무보정:0/201 I2C오류:0
                              ↑
```

I2C 읽기 실패를 누적해 표시한다. 이 값이 계속 오르면 풀업이나 배선을 의심한다.
