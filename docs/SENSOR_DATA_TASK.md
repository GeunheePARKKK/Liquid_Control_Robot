\# 담당 2: 이중 IMU 및 데이터



\## 목표



하부 베이스와 상부 트레이의 IMU를 안정적으로 읽고, 센서별 물리 단위 데이터와 유효 상태를 제어 모듈에 제공합니다. 이후 슬로싱 주파수 학습에 사용할 데이터 형식을 준비합니다.



\## AI에 제공할 자료



1\. `docs/ai-handoff/COMMON\_CONTEXT.md`

2\. 이 문서

3\. `firmware/gimbal\_control/Sensor.h`

4\. `firmware/gimbal\_control/Sensor.cpp`

5\. `firmware/gimbal\_control/Config.h` — 읽기 전용

6\. 실제로 확정된 각 IMU의 공식 데이터시트

7\. 검증된 기존 센서 코드가 있다면 센서 관련 부분만 별도 제공



\## 작업 전 필수 확인



Config에 설정할 두 IMU의 정확한 모델, CS 핀과 공용 SPI 핀을 먼저 확정해야 합니다. 공식 데이터시트에서 다음 항목을 확인하지 못하면 레지스터 코드를 추측하지 않습니다.



\- WHO\_AM\_I 기대값

\- 지원 SPI 모드와 최대 클럭

\- 초기화 레지스터

\- 연속 읽기 시작 주소와 바이트 순서

\- 가속도·자이로 측정 범위와 스케일

\- 센서 장착 축 변환



서로 다른 IMU 모델을 사용하면 각 센서의 초기화, SPI 설정, 엔디언과 스케일을 분리합니다.



\## 파일 소유권



\- 수정 가능: `Sensor.h`, `Sensor.cpp`, 승인된 데이터 관련 파일

\- 읽기 전용: `Config.h/.cpp`

\- 수정 금지: `Gimbal.\*`, `Control.\*`, `gimbal\_control.ino`



\## 구현 책임



\- Config에서 SPI 핀, CS 핀, 센서 종류와 타임아웃을 읽어 초기화

\- 센서별 WHO\_AM\_I 검사와 초기화 상태 반환

\- 원시값을 m/s²와 rad/s로 변환

\- 정지 상태 자이로 바이어스 측정

\- 필요한 가속도 보정값 제공

\- 센서별 샘플 타임스탬프와 `valid` 상태 제공

\- 포화, 읽기 실패와 오래된 데이터 검출

\- 두 센서 데이터를 일관된 베이스·트레이 축 기준으로 제공

\- 시간, 두 IMU, 목표각과 모터 피드백을 결합할 CSV 열 정의 제안



\## 공개 인터페이스 목표



```cpp

bool initSensors();

bool calibrateSensorsStationary(uint16\_t sampleCount);

bool readSensors(ImuPair\& out);

bool sensorsHealthy(uint32\_t nowUs);

```



센서 모듈이 자세 추정까지 담당하게 변경하려면 통합 담당자와 먼저 인터페이스를 합의합니다.



\## 구현 순서



1\. 실제 IMU 모델과 공식 데이터시트 확정

2\. 센서별 단독 WHO\_AM\_I 시험

3\. 센서별 원시값과 물리 단위 변환 시험

4\. 두 센서 공용 SPI 동시 구성

5\. 정지 바이어스 보정

6\. 축 방향과 부호 검증

7\. 목표 제어주기에서 누락과 지연 측정

8\. 통합 데이터 형식 제안



\## 안전 및 금지사항



\- 센서 초기화 실패를 정상 상태로 숨기지 않습니다.

\- 한 센서의 레지스터, 스케일과 바이트 순서를 다른 센서에 재사용하지 않습니다.

\- 모터, CAN, P와 ZV 코드를 Sensor에 넣지 않습니다.

\- 핀과 센서 종류를 `Sensor` 파일에 하드코딩하지 않습니다.

\- 검증되지 않은 데이터를 정상 CNN 학습 데이터로 표시하지 않습니다.



\## 완료 기준



\- 각 센서의 WHO\_AM\_I가 공식 기대값과 일치함

\- 정지 상태에서 가속도 크기가 약 1 g이고 자이로 평균이 0에 가까움

\- 알려진 방향으로 기울일 때 축과 부호가 정의와 일치함

\- 두 센서를 함께 읽어도 데이터가 섞이지 않음

\- 목표 제어주기에서 샘플 시각과 유효 상태가 안정적으로 갱신됨

\- 센서를 분리하면 실패 상태를 보고함
